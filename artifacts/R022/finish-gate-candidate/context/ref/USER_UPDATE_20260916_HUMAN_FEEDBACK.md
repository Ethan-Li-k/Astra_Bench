## 人工反馈与信息对齐

人工标注工作写域 human-feedback/，独立于正在运行的campaign。主控/地面搬运只读公共案例及已提交标注，不修改原失败证据。策略与用户共用同一观测包版本：RGB、相机标定、命名机器人状态、动作/时序、实际机器人跟踪反馈、可调用工具合同、当时task spec和skill版本。公开判断摘要分离观察事实、假设、证据、不确定性、预期现象与下一检验，不导出模型私有推理。没有记录的信息明确标不可观测，不能补造。host物体位姿、接触、奖励、关节真值、oracle轨迹不进入策略或公共人工纠错包；额外host审计单独保留，不能暗中变成视觉线索。

每例先让用户观察，再对照策略的公开判断，避免诱导；用户已知失败或已看过结果时如实记录，不称盲测。用户只需选方向/标关键帧、指出可见证据、说明“看到什么才继续”及适用边界；不要求精确坐标或低层控制示教。记录用户原话与agent提炼规则，规则状态先为human_proposed，不能直接写成物理真相。针对不明确的条件做短追问，让用户确认提炼是否准确。

收到纠正后的闭环：固定原始证据 -> 复现失败(同初态/版本、旧动作，只计诊断，不加成功数) -> 一次只改变用户指出的判断条件或规划规则 -> 真物理新回合验证 -> 若仍失败给用户同结构对照而非重复大段总结 -> 在新重置/不同布局上检验迁移 -> 通过后按机制晋升公共skill。若旧checkpoint/完整状态无法恢复，明确复现误差，不伪称完全同条件。

学习载体是用户显式表述的判断规则、ICL例子、反例与外部记忆，不声称GPT权重被训练或已学会用户的全部思考。保留证据时间点、适用条件、何时不适用、用户纠正前后的预测、错误类别、验证结果和版本。评估时先让模型在相同公开信息下独立作判断，再对照用户意见；认可率不等于物理成功，必须另测任务结果与人工求助频率。
