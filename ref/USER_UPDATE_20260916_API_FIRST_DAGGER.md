# 最新覆盖：API用尽后才用20x；失败导向学习与纠正聚合

用户原话：API额度用完再使用辅助20x套餐；借鉴DAgger，失败最多的任务多尝试，成功任务少尝试，成功任务先成功8–10次以上。本文件覆盖旧账户顺序与学习调度，其他环境、审计、正式测评协议保持。

## 严格账户顺序

- 所有新模型回合，包括actor、工程、reviewer、监督与自动接续，默认且优先仅用既有授权API，固定gpt-6-astra/xhigh。只有已有请求明确给出API额度耗尽/insufficient_quota等可信错误，或本地共享60000 CNY预算确已无法覆盖下一请求，才允许切换隔离辅助20x账号。不得主动查询余额/配额来触发；每1500报告、未知费用与预留保留。
- 普通429限流、503、网络故障、慢推理、上下文问题、审批/接线/凭据故障不能当额度耗尽；保留请求状态，按原明确恢复合同处理，不暗换套餐、不重放未知请求。预算是否耗尽与接口是否可用分别记录。
- 所有接续选择器必须实际执行 API 优先顺序并验证，不只更改文字。API预算恢复不自动往返切换，保留来源与切换证据。
- 禁止使用本地主账号 Codex Pro Lite。已有API或辅助账号在途请求完整等待，完成边界后不再新开辅助回合，除非已满足API耗尽条件。现有物理环境、动作ACK、公开history保留；不能为切换重置或复执行动作。原watcher的PAUSE只阻止下一错误后端启动，不取消在途进程；恢复唯一watcher前须验证新顺序。
- 框架/接续器唯一owner维护运行时及中央发布；本线程仅规则与队列交接，不伪造quota事件或API-route证据，不新建第二watcher。

## 学习资源分配

- 成功任务降低学习频率的门槛取用户范围上限：同一精确task、同一完整固定候选与控制合同下，至少10个独立reset、完整物理执行、独立审计成功；同时仍满足原固定候选五连胜条件。两项计数分别记录，旧跨版本/近似变体/原生假阳性/回放不凑10。
- 候选/控制/记忆/反馈变化后重新累计当前候选，旧成功作为有条件来源保留；自主与人工辅助分层。这里是学习降频门槛，不改已预登记正式测评样本数或以正式失败改变同批策略。
- 首先保证六个精确入口都有首次尝试；未完成控制适配的任务得到诊断资源，不伪装任务回合。之后通常每5个可分配学习名额，至多1个用于已达门槛任务的回归，其余投向未达门槛任务；没有已掌握任务则全部用于未达标任务。无须额外大调度框架，沿用唯一主管现有排程。
- 未达标任务按近期最多10次可比独立完整尝试的失败率、重复失败机制、成功数缺口和修正是否就绪排序，保留轮转机会，不用历史总失败数永久垄断资源。优先有新假设/纠正/控制修复的重试，而非相同命令无限重复。
- 基础设施中断、推理等待、渲染失配、预算截断、未封口回合不当作任务能力失败增加训练权重；分别修复基础设施。达到人工门槛则发起代表性求助，期间继续其他可推进任务。
- 已掌握任务继续少量回归与跨任务原子复用；若新条件下复现退化，回到较高学习优先级，而不是凭旧10次永远标掌握。
- 正式冻结评测继续每任务L0/L1/L2各10、总180，固定种子/候选/协议，无在线纠正或成败自适应选样、删样、补成功；自适应只用于学习，正式结果不混入学习调度胜率。

## DAgger思想如何适用

原论文 Algorithm3.1（https://proceedings.mlr.press/v15/ross11a/ross11a.pdf）在当前策略实际访问的状态上获取专家动作，将纠正数据聚合后更新策略。失败任务多采样本身不是DAgger。

当前不能微调GPT，采用DAgger启发的纠正聚合：实际访问状态/失败阶段 → 许可RGB与公开动作、简短判断依据 → 人工纠正或明确来源的修复提案 → 原条件复现与修正验证 → 中央更新skill/可检索经验 → 新独立尝试。不是声称已经实现标准DAgger、获得其理论保证或训练了新模型。

- 优先保存失败前最后一个可恢复决策点，而非只存最后摔倒/抓空帧。记录任务、候选/control、阶段、公开观察与动作、应改决策、前置/退出证据、标签来源、验证episode与结果。
- 人类标签、成功轨迹提炼、模型自评提案分开；模型自评不是专家真值。沿已有记忆格式扩展最少字段，不新造角色/MoE或泛化框架。
- 同任务/阶段/机制至少3次可比独立失败且自主修订仍无解，及时给用户代表视频和1–3个具体问答；不要求用户逐条看全部轨迹。回答可修正空间关系、抓取阶段门槛或长程计划，保留适用条件与原话。
- 人工辅助数据不混作无辅助Direct；评测冻结后不读新人工反馈。未来若单独FT π0.5，可使用经复现验证的纠正轨迹训练，但本指令不自动启动FT。

验收：原维护者先复现旧后端默认顺序错误，测试API可用时辅助被拒、明确耗尽才放行、一般429/503不切、未知请求不重发；调度测试未达到10不降频、达标后降低而不饿死、候选变更归零、未封口/系统错误不混失败、正式180计划不变。网页公开当前后端/来源证据、10次门槛进度、下一任务选择原因及待人工纠正；源码发布与实际加载分别回执。
