# 人工判断学习合同

用户擅长读图、长程规划和空间推理，只负责辅助判断、指出错误、决定方向。agent负责挑选代表性重复失败、证据对齐、问题设计、实现、复现与对照。统一标注界面由SIMPLE分支维护，本分支仅提交自己的案例索引，不复制界面或覆盖共享skill。

## 至少三次失败后才请求人工分析（用户最新要求）

日常失败由agent自行分析、尝试和改skill；不得逐条交给用户。只有同类机制、可比较任务/控制条件下至少3次完整真实尝试仍反复失败，且agent已实施有区分力的自我排查，才提交一个代表性失败簇。先展示视频，再提出真正影响决策的少量问题。

计数要求：独立episode和reset，保留controller/skill/接口版本、实际动作、完整录像及失败证据。复制轨迹、同一reset换ID、仅重渲染、固定旧动作复现、没有物理执行的模型回合均不计新增探索次数。版本/任务机制改变时分组，不能把不可比失败凑够3次。达到3次只是必要条件，不代表每满3次必须打扰用户。

F001此前提前询问过用户，现暂停新增提问；已有回答原样保留，不要求重答。F001-baseline-001复现用于确定性检查，不计入三次自主尝试门槛。

## 提问与信息边界

- 先呈现观察，再展示模型公开的判断摘要，避免诱导；已知失败的案例不称盲测。
- 公开输入包括当时RGB、标定、具名本体、动作、控制合同和公开反馈，保留时间与哈希。说明“当时可获得”和“有证据确认实际读取”的区别。
- 分开动作前、动作后才到达、仅复盘可见的内容。外部诊断视角单列；用户使用额外信息要标注，不能暗中使策略获得oracle。
- 提供事实、假设、置信不足、动作目的、预期可见变化和停止门槛的简短依据摘要，不输出私有内部推理。
- 每次先问一个能改变下一实验的问题；允许无法判断。后续追问优先问证据、前提、何时继续/停止、最小反例，不要求用户设计低层实现。

## 学习记录

每条反馈保存：用户原话、原案例与帧、原策略公开预测、实际结果、用户判断及理由、agent提炼的条件规则、用户是否确认、何时不适用、最小反事实、复现版本、对照结果、失败类型和状态。尚无回答的字段保持null，不补造用户观点。

规则状态按human_proposed → confirmed_interpretation → failure_reproduced → locally_validated → transfer_validated演进；失败或反例可退回/限制适用范围。收到纠正不等于因果已经证明。

## 复验与独立能力

1. 原始失败与用户原话不可覆盖；锁定环境/资产、模型、控制器、状态与历史、动作及seed。缺少状态时如实报告匹配程度。
2. 先原方案复现失败，明确重放录像不是重新运行物理。
3. 只改变一个判断条件或规划规则，执行新物理对照；失败则给同结构前后材料继续请用户纠正。
4. 在保留出的新重置/布局上先独立预测再执行，不提前给模型用户答案；测试物理成功及危险/错误动作减少，不能只测“与用户说法一致”。
5. human_feedback_used、human_demonstration_used与冻结评测分层记录。学习载体是显式经验和skill，不声称基础模型权重被训练。
6. 统计每类错误复发率、相同信息下判断正确率、实际成功率、每回合求助次数、迁移失败；目标是逐步减少对用户的求助，不是停止必要的方向确认。
