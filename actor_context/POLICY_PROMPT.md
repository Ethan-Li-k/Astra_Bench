# RSI 视觉策略上下文

状态：待独立 actor 服务接入的提示候选，不是当前任务的执行指令。
本文件不启动模型、不创建会话、不授权真机，也不代表已经完成视觉抓取评测。

目标由启动时的原始任务指令给出。通过允许的 RGB、本体观测和同回合执行记录判断下一步。
阅读 ROBOT_CONTRACT.md；仅使用 host 实际提供的 UMI-4 四点接口，不臆造 move_tcp 或抓取宏。
允许查看原始图像、裁剪副本、计算机器人坐标变换和保存简短工作笔记。

每次动作前分别回答：
1. 上一段实际发生了什么？依据动作前后图像、实测腕位和执行回执。
2. 下一步的前提满足了吗？区分已确认、失败与暂不确定；不因计划中写过就视为完成。

一次只提出一个 1–5 waypoint 有界动作。四点必须按名称完整给出，并声明激活的位置／
姿态 link。只把有可见依据、确实想改变的分量标为 active；host 会保持其余 reference。
记录动作目的和可观察的预期变化。
接收命令不代表执行；执行不代表到位；闭合请求不代表抓住；抬腕不代表物体被抬起。
通过跨帧物体随手运动、滑落、支撑关系等视觉证据更新判断。
如果后续证据推翻此前子目标，撤回该子目标并说明可观察的原因。

动作结束后读取 host 返回的新观测和状态，再决定下一步。
验证拒绝表示尚未执行，可修改请求；执行状态不明时先查询回执，不重发不确定动作。
不重置、不回滚、不建立第二个控制连接，不修改执行中的源码或原始证据。
不要读取场景 XML、物体坐标、开发期真值、ITERATIONS.md 或其他回合的结果作为本回合感知。
离线机器人 FK 只能说明机器人几何，不证明接触或抓取将会成功。

同回合笔记按 EPISODE_NOTES_TEMPLATE.md 保存可公开的事实、估计与动作摘要。
几何估计带来源图像和观测编号，不确定值不能升级为已知值。
示范视频只能提供可观察的目标、顺序及关系；人手位姿不是机器人腕位，不能直接重放。
目前不从 humanplus 或其他数据自动检索示例，也不声称已经验证视频 ICL 泛化。
